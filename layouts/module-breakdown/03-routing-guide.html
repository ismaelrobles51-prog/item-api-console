Module purpose

Routing Guide

Resolve the shipment’s final service terminal and approved network path from current location to destination.

Upstream data→Routing Guide→Downstream handoff

Inputs / Data

  • Current terminal
  • Consignee state and five-digit ZIP
  • routing.xlsx origin-specific matrix
  • Fallback state and ZIP coverage rules
  • Uploaded planner routing plan

Core workflow

Resolve destination terminal from matrix or fallback rules
Check configured manual exceptions
Determine whether the final terminal can be served directly
Apply LAX hub routing for configured sub-terminal destinations
Return the full path and immediate next terminal

Key business logic

  • Network terminals include DFW, LAX, ORD, SAC, HAY, PHX, MCO, SEA, EWR, NHT and ATL in the current selector
  • Default regional coverage is derived from state/ZIP bands
  • Non-LAX freight headed to SAC, HAY, PHX or SLC may route through LAX
  • A routing-plan row can preserve planner intent even when inferred routing differs

Outputs / Next step

  • Final terminal, path, next terminal and exception state to Linehaul Manager

KPIs

  • Routed vs exception orders
  • Direct vs hub movement
  • Matrix coverage
  • Plan-match percentage

Alerts / Exceptions

  • CO/MT/WY manual-route exception
  • Missing matrix route
  • Conflicting inferred and planned lane
  • Unknown ZIP or terminal
