Module purpose

Trip Completion / Next-Leg Evaluation

Complete the current trip leg, update the order’s physical position, and decide whether delivery or another linehaul leg comes next.

Upstream data→Trip Completion / Next-Leg Evaluation→Downstream handoff

Inputs / Data

  • Completed trip and destination terminal
  • Orders and manifest reconciliation
  • Current terminal after arrival
  • Final destination terminal
  • Remaining approved routing path

Core workflow

Confirm trip/stop completion
Set each order’s current terminal to the arrival terminal
Compare current terminal with final terminal
If equal, release to final-mile/delivery flow
If different, re-run routing and return freight to an active next-leg lane

Key business logic

  • Linehaul Complete means a leg has ended, not necessarily the shipment
  • ORD → LAX completion changes current terminal to LAX while final remains SAC
  • Because LAX ≠ SAC, next terminal becomes SAC and active lane becomes LAX → SAC
  • Only current = final ends the linehaul routing cycle

Outputs / Next step

  • Next-leg eligible order back to Routing Guide / Linehaul Manager
  • Destination freight to Out-for-Delivery
  • Completed-trip facts to Analytics and Audit

KPIs

  • Leg cycle time
  • Connection dwell
  • Multi-leg completion rate
  • Final-terminal accuracy

Alerts / Exceptions

  • Stranded freight after linehaul complete
  • Current/final terminal mismatch without next route
  • Incomplete manifest or stop reconciliation
  • Duplicate next-leg assignment
